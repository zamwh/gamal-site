2. WHAT THE SYSTEM IS
=====================================================================
A complete system for a gold shop in Ibb, Yemen:
  "جمال المشرقي للذهب والمجوهرات"
  Address shown to customers: «بجوار البوابة الرئيسية لمركز جرعان، إب»
  The owner is Nashwan's brother-in-law. Internally there are 3 shops
  (branches), but customers only ever see ONE shop (the "البوابة" one).

Parts:
 a) Website (customer storefront): pieces with photos, today's gold price,
    gold value calculator, piece pages /p/CODE, buy/reserve flow,
    an AI sales advisor (text chat) and a voice advisor.
 b) Admin dashboard at /admin: prices, pieces, photos, AI settings,
    voice, phone calls, Telegram, POS linking, analytics, chats.
 c) Telegram bot @AlmshrqiGoldBot — STAFF ONLY: sale/reservation
    notices, piece photos from the phone, reports, internal agent,
    the shop channel, and (new) full control «⚙️ التحكم».
 d) Telegram channel of the shop: every new piece is posted with its
    photos; sold pieces become «تم البيع» with a «أبغى مثلها» button.
 e) POS desktop program (Windows, Python + pywebview) for the shop
    counter: cashier F1–F8, stock, suppliers, customers, shifts,
    reports, invoices A4/A5. Works offline and syncs to the server.
 f) Phone calls: the AI advisor (female voice) calls premium customers
    when gold drops, in Gulf dialect, under 2 minutes.
 g) WhatsApp agent: BUILT and ready (whatsapp.py), waiting only for Meta's
    values to be typed in the admin (section 11b).

Tech: Python standard library only on the server (no frameworks),
SQLite databases, plain HTML/CSS/JS front end, OpenAI APIs.

4. HOW AN UPDATE REACHES THE LIVE SITE
=====================================================================
1. Change code locally, run the tests (section 15).
2. Commit and push to GitHub main.
3. Within about a minute the server pulls and restarts.
4. Check: open the site, open /admin, press «🩺 حالة النظام» in Telegram.
   The status shows the running commit ("النسخة").
Static files (site/js/*.js) are cached by browsers: when you change one,
bump its ?v= number in site/index.html or site/admin.html.

Undo a bad update (safe way):
   git revert <bad_commit>   then push. The server pulls the revert.
Never force-push over main.

9. THE CUSTOMER SALES AGENT (TEXT)
=====================================================================
- Model: gpt-6-luna for all replies (owner's decision). A stronger model
  exists in settings but is not used by default.
- Every number (price, weight, stock) comes from a tool reading the DB.
- sales_rules.route() classifies each message; common questions get ready
  answers with no AI cost (greeting, location, hours, gold price, karat,
  returns, exchange, repair, selling gold to the shop, price locking,
  deposit, installments, discount, complaint, human request, "are you a
  bot", forecasts, competitor, account number, prompt-injection...).
- check_reply() blocks: numbers without a source, false scarcity,
  "your taste" unless the customer said it, internal words, banned words,
  female relatives, the word «فرع/فروع», forbidden promises, karat other
  than 21, repeats, more than one question, invented stock stories.
  It rewrites once, then falls back to a safe reply.
- Hands over to the sales team after 2 misunderstandings, the same
  question 3 times, 16 messages, or a ready bride-set buyer.
- «وصل حديثاً»: EVERY newly added piece (any category, including clean
  used pieces) shows there for 14 days (setting showcase.new_days), and
  is always in its own type section from day one. After 14 days it simply
  leaves «وصل حديثاً». Pieces synced from the POS keep these 14 days even
  if the POS sent no date (pos_sync keep_new). The owner can still change
  a piece's days from the admin/POS (set_showcase).
- Deposit button «احجزها بعربون 10%» exists on the site; the agent never
  offers it first; if asked: from the piece page, holds 24 h only, does
  not fix the price.
- Making charge (المصنعية) is internal and never shown or mentioned.
- 25 "tough customer" scenarios ×5 runs passed 25/25 (tests/tough25.py).

11. PHONE CALLS TO PREMIUM CUSTOMERS
=====================================================================
Goal: when gold drops, the AI advisor calls premium customers.
Owner's plan: 40 premium customers; normal drop -> call 10, strong
drop -> call 20; each call under 2 minutes.

How it works now ("callback" mode, the one that works):
 1. Server calls Zadarma API GET /v1/request/callback/ with
    from = PBX extension 100, to = the customer number WITH "+",
    sip = 101. (Signature: base64(hmac_sha1_hex(secret,
    method + query + md5(query))); header Authorization: key:sig.)
 2. Zadarma PBX extension 100 is forwarded "Always active" to the
    external SIP server  sip:proj_XXXX@sip.api.openai.com;transport=tls
 3. OpenAI sends a webhook to /api/phone/webhook
    (event live.transport.incoming). The server verifies the signature,
    matches the latest "dialing" call within 90 s, and accepts with the
    call instructions (script + voice). Unknown calls are rejected (486).
 4. The server attaches to the call's sideband WebSocket
    (wss://api.openai.com/v1/live/sessions/{id}/attach): tells the
    advisor to wrap up at 105 s, hangs up at 135 s from pickup,
    collects the transcript and cost.
 5. A Telegram card is sent; tap for the transcript.
Rules in code:
 - Yemeni numbers (+967) ONLY. Zadarma's route to Saudi answered with
   fake recordings and billed minutes.
 - per_day limit 25; one call at a time for bulk calling.
 - The webhook needs a stable public URL. If the tunnel address changes,
   update the webhook URL in the OpenAI project settings.
Script (phone.py SCRIPT): Gulf dialect only; greets by name and asks how
he is; «معك المستشارة الآلية لمجوهرات جمال المشرقي»; gold went down;
offers the newest collections on WhatsApp; no piece prices on the call;
no discounts, no making charge, no female relatives; closes politely.
Pronunciation guide with diacritics (المَشْرِقي، جَرْعان، إِبّ ...) and
natural, situational tone (light laugh, excitement for the news, calm
if busy) were added 2026-11-27.
Voice: coral (female), loud and clear. Picker in admin: coral, marin,
shimmer, echo, ash.
Recordings: in Zadarma's web account, enable "Call recording -> To the
cloud" on extensions 100/101. Transcripts are saved by our system anyway.
Failed approach (do not retry): OpenAI dialing out directly over SIP
through Zadarma returned 480.
After the call: when the card says the customer agreed (the advisor says
the fixed sentence «أبشر، أرسلها لك على طول بعد المكالمة.»), the card
gets a button «📲 أرسل له العروض على الواتساب» (callback wo:<id>) that
sends the approved offers template with his name. With
whatsapp.auto_after_call on, it is sent by itself.

11b. WHATSAPP (BUILT, READY TO LINK)
=====================================================================
File: whatsapp.py. Official Meta WhatsApp Cloud API (graph.facebook.com),
no unofficial tools (no ban risk).
What it does once linked:
 - A customer writes -> the SAME sales agent as the website answers
   (session "wa<digits>"); [[CODE]] markers removed; up to 3 pieces sent
   as photo + caption (title, weight, karat, today's price, piece link).
   Photos need the public https address (app.public_url).
 - One answer at a time per customer; 40 agent answers per customer per
   day; the agent's own daily/monthly money caps still apply.
 - Coexistence: when someone from the shop answers from the WhatsApp
   Business app, Meta sends an echo (smb_message_echoes); the agent then
   stays quiet with that customer for 30 minutes.
 - First message of a new customer -> short notice on Telegram.
 - Agent switched off but linked -> one polite welcome, then silence;
   staff answer from the phone.
 - All messages kept in table wa_messages (in/out, who, status).
 - Duplicate deliveries from Meta are answered once.
 - Business-started messages (e.g. after a call) MUST be an approved
   template; free text is only allowed within 24 h of the customer's
   last message (Meta error 131047 otherwise).
Linking steps (owner, once):
 1. Meta Business account + a Meta app of type Business with the
    WhatsApp product (developers.facebook.com).
 2. Add the shop's number. Keep it on the phone with Coexistence if it is
    on the WhatsApp BUSINESS app (2.24.17+) — Embedded Signup with the
    coexistence option. Otherwise a new Yemeni SIM.
 3. Create a System User with a permanent token (whatsapp_business_messaging
    + whatsapp_business_management).
 4. In /admin > Settings > «الواتساب (وكيل المبيعات)» type: Phone number
    ID, WABA ID, the permanent token, App secret (App settings > Basic),
    and the offers template name (optional). Save.
 5. In Meta > WhatsApp > Configuration > Webhook: Callback URL =
    <public address>/api/wa/webhook, Verify token = the one shown in the
    admin. Subscribe to "messages" (and "smb_message_echoes" with
    coexistence).

13. EMERGENCY PLAYBOOK
=====================================================================
A) Customers abuse the agent / spending jumps
   Telegram: ⚙️ التحكم > 🤖 وكيل الزبائن > ⛔ وقّفه.
   Same for 🎙️ الصوت للزبائن and 📞 المكالمات.
B) The site feels stuck / errors
   Telegram: ⚙️ التحكم > 🔄 إعادة تشغيل > نعم. Wait 1 minute, then
   🩺 حالة النظام. If the bot itself does not answer, the server process
   is down: on the server run
     sudo systemctl status gamal-site --no-pager   (or the service name
     found with: systemctl list-units --all | grep -i gamal)
     sudo systemctl restart <that service>
C) A code update broke something
   On GitHub: revert the last commit (git revert <hash>, push). The server
   pulls it within a minute. Status shows the running version.
D) Site link stopped working
   The trycloudflare tunnel changed. On the server:
     grep -o 'https://[a-z0-9-]*\.trycloudflare\.com' ~/tunnel.log | tail -1
   If no tunnel is running, start it again (from نشر_الموقع.txt step 3).
   Then update the webhook URL in OpenAI (phone calls) and share the new
   link. Permanent fix: a stable domain (section 17).
E) Gold price is old
   /price SELL BUY in Telegram. The status shows the last update date.
F) Need a copy of the data
   ⚙️ التحكم > 💾 نسخة احتياطية: the DB file arrives in Telegram.
   Daily automatic backups also go to data/backups on the server.
G) Restore a backup (only if data is lost): stop the service, copy the
   backup .db over data/<mode>.db (keep the broken file renamed, never
   delete), start the service.

14. HOW TO MAKE A SAFE CHANGE (STEP BY STEP)
=====================================================================
1. git clone https://github.com/zamwh/gamal-site && cd gamal-site
2. Read the file(s) you will change and their test in tests/.
3. Make the smallest change that fixes the problem.
4. Run the related test, then the whole suite:
     for t in tests/*_test.py; do python3 $t | tail -1; done
5. If a JS file changed, bump its ?v= number in the HTML.
6. Commit with a clear message; push to main.
7. Verify on the live site and with 🩺 حالة النظام.
8. Never put secrets in code. Never edit data/*.db by hand on the server
   without a backup.
Running locally:  python3 server.py --mode demo --port 8095 --data ./data
  then open http://127.0.0.1:8095/ and /admin (demo users are created
  in the demo DB; change passwords on any real deployment).

18. HISTORY OF KEY DECISIONS AND LESSONS LEARNED
=====================================================================
- Bot is for staff only; customers go to the channel and WhatsApp.
- One public shop only; other shops' pieces are hidden from customers.
- Telegram channel first because official WhatsApp does not allow
  automated posting to WhatsApp Channels.
- No appointment booking/visits (market not ready).
- No staff training/simulation; training targets the AI agent only.
- ElevenLabs removed; OpenAI only for all voice.
- Phone: Twilio ($20) rejected as too expensive; Zadarma with $5 top-ups.
  The owner did not want his Saudi number shown; a Canada virtual number
  was bought ($4/month, no documents). Yemeni customers see a local
  number.
- Zadarma Saudi route gave fake answers/recordings and billed minutes
  -> calls limited to Yemen; a refund request was drafted.
- Several Zadarma callback failures were solved by: sip=101 (not the SIP
  login), "+" in the destination, predicted mode off, and connecting a
  virtual number to the account (the call audio literally said "Please
  connect the phone number in your Zadarma personal account").
- First surprise call to the shop owner succeeded.
- Lesson: verify causes from provider statistics, support and docs
  before asking the owner to pay for anything.
